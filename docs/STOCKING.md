# Stocking maintenance

Read `docs/UPDATE-PROTOCOL.md` before updating research. Stocking reviews cover every lake, pond and reservoir, including inactive accesses. Match access records to the same waterbody and apply the same stocking facts to each one. Keep the access-specific ratings and restrictions separate.

## Evidence and fields

Store the current review in each location's `stocking` field. Include the waterbody name, status, summary, limitations, checked date, next review date, source IDs and events. The detail panel displays these fields, and the public corpus exports them. Use `confirmed-record` when an agency or fishery manager reports a completed release. Use `schedule-only` when the evidence is a plan. Use `no-record` for a completed search without a matching event, `discontinued` for affirmative evidence that stocking stopped, `private-managed` for a managed paid fishery without public delivery records, and `unavailable` for a material source failure after trying reasonable alternatives. A missing record does not establish that a water has never been stocked. Each event has a start date, optional end date, `confirmed` or `scheduled` status, species, quantity or null, size or null, and source IDs. Use notes for annual allocations, imprecise windows and special restrictions. Keep event dates separate from retrieval dates. A past scheduled week remains scheduled until a source confirms delivery. Avoid representing an annual allocation as the number still due in a later window. WDFW's catchable-plant view omits smaller releases. Read the underlying public fish-plant data when reviewing fry, fingerlings or kokanee, and match county and waterbody identifiers. ODFW's schedule gives planned weeks and size categories. Check the current regional recreation report for a completed-stocking statement. Use private fishery managers for managed ponds. Try aliases and additional sources when a query returns no rows. Check pagination and result limits before claiming a complete search.

## Ratings and preservation

A fry release does not create immediate dinner-size fish. Neither an allocation nor a catchable delivery establishes how many fish remain, where they can be caught, or whether an access is open. Reconsider seasonal judgments only when the new evidence changes likely bank prospects. Keep unknown ratings null and use a short, dated override when warranted. Preserve monthly profiles unless new evidence changes the usual annual pattern. Preserve historical sources and research logs. Replace the current structured review after a new check, and retain a dated evidence record when correcting earlier claims. Update only dates for claims actually checked. Preserve availability overrides, access restrictions, private journals, favorites, filters and shared weights.

## Weekly publication

The Thursday stocking automation performs research and publishes accepted changes. The next review date is a research reminder. It does not claim that a refresh has run or that a scheduled delivery occurred. Follow the currently authoritative deployment's publishing workflow. Run model, seasonal and stocking tests, typecheck, and the production build. Verify successful deployment and reread changed research. After a hosting migration, update the automation destination only after verifying the new production site and its source repository.
